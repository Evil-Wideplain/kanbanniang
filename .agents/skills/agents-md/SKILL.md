# AGENTS.md 写作与维护

> AGENTS.md 是「写给 AI Agent 的 README」：人类同事有 README 和口头传承，Agent 只有仓库里的文字。本 skill 是写作与维护的完整指南；仓库根 AGENTS.md 的「维护」节只保留摘要与指针。

## 定位与分工

- 受众是 AI 编码 Agent（Codex、opencode、Cursor 等支持 agents.md 标准，<https://agents.md/>）。
- README 面向使用者/访客：介绍、安装、用法；AGENTS.md 面向改代码的 Agent：命令、结构、约束、验证流程。
- 同一信息只写一处：写了双份，两份必然漂移（「双份真相」是最常见的文档病）。

## 核心原则

1. 命令优先：给可直接复制的精确命令（含 flag、workdir、必过标记）。
2. 保持简短：根文件 100 行以内；细节做渐进披露——放模块页或 skill，主文件只留摘要 + 指针。
3. 可执行优于口号：「提交前跑 `make lint`」优于「保证代码质量」。
4. 就近生效：根文件管全局；模块细则放模块目录，离代码越近越不易过期。
5. 活文档：随代码同步更新；过期文档比没有更糟——Agent 会当真。

风格：中文；表格、编号列表优先于散文；不依赖 emoji 表达。

## 根文件结构（七区块）

| 区块 | 要点 |
|------|------|
| 一句话简介 | 2 行内：项目是什么、子文档在哪 |
| 常用命令 | 精确到 flag，标注「必过/必跑」 |
| 项目结构 | 目录 → 职责 → 细则链接，只列顶层 |
| 核心链路 | 一张图或 3-5 步 |
| 硬性规则速记 | 每条一行，细则链到 skill |
| 提交前验证清单 | 编号步骤，可直接执行 |
| 维护机制 | 压缩到 2-3 条 |

## 模块页模板（7 段式）

| # | Section | 必须 | 说明 |
|---|---------|------|------|
| 1 | `## 职责` | 是 | 2-3 句话：这个目录做什么 |
| 2 | `## 关键文件` | 是 | 路径 → 作用（含边界）表，只列入口/接口 |
| 3 | `## 核心模式` / `## 核心流程` | 按需 | 模块特有的设计或请求链路 |
| 4 | `## 开发注意事项` | 是 | 陷阱、隐性约束，bullet list |
| 5 | `## 依赖关系` | 是 | 依赖谁、被谁依赖、方向 |
| 6 | `## References` | 按需 | skill / 设计文档链接（相对 md 链接） |
| 7 | `## See Also` | 是 | 交叉链接；首行「← 上级：[[仓库根路径]]」 |

约定：

- front-matter 固定字段：`title / created / updated / type / tags / description / sources`。
- AGENTS.md 互链用 wiki 链接且路径从仓库根写全（如 `[[src/tauri/AGENTS.md]]`），避免同名歧义；引用 skill / 普通文档用相对 md 链接。
- 新增目录时，同时更新父级与根级索引。

## 内置 skill 约定

- 位置 `.agents/skills/<name>/SKILL.md`，目录名与 front-matter `name` 一致（小写连字符）。
- front-matter：`name` + `description`；description 写清「做什么 + 何时加载 + 触发词」（1-1024 字符）。
- skill 是任务型细则（按需加载），不写项目介绍；与 AGENTS.md 摘要互为指针，不得双份真相。

## 内容放哪儿：归属决策

| 内容 | 放哪 | 例子 |
|------|------|------|
| 所有编码任务都要遵守的硬规则 | 根速记（细则进 skill） | 依赖单向、契约成对维护 |
| 模块专属流程/陷阱 | 该模块 AGENTS.md | 模型热切换「先建后销」 |
| 做特定任务才需要的方法论 | 内置 skill（`.agents/skills/`） | 注释规范、CRAP 修复流程 |
| 人类阅读为主的背景/教程 | `docs/` 或 README | 模型接入说明 |
| 可执行命令 | 根「常用命令」；模块页可补充 | `make lint`、冒烟测试 |

判断法：问「Agent 什么时候需要它」——每次都要的放根/模块页；按任务要的放 skill；人和 Agent 偶尔查的放 docs/。

## 反模式

| 反模式 | 后果 | 改正 |
|--------|------|------|
| 长篇散文、大段架构介绍 | 重点被淹没、浪费上下文 | 一句话 + 指针，细节进 skill/docs |
| 命令含糊（「构建一下」） | Agent 猜错工具链 | 给精确命令与 workdir |
| 抽象口号（「保持整洁」） | 不可执行、不可验证 | 换成可检查的规则 |
| 只维护根文件 | 子目录 Agent 看不到就近规则 | 就近建立模块页 |
| 双份真相 | 两处必然漂移、互相矛盾 | 单一来源，其余只放指针 |
| 写完不维护 | 误导 Agent，比没有更糟 | 变更即同步，顺手更新 `updated` |

## 更新时机与提交前自检

同步时机：

- 关键文件、公开接口、事件契约、依赖关系、目录结构变更 → 更新对应 AGENTS.md。
- 规范（架构/注释/日志等）变更 → 先改 `.agents/skills/` 对应 SKILL.md，再同步 AGENTS.md 的摘要与引用。

提交前自检：

1. 命令可直接复制执行，路径与 workdir 正确；
2. 链接无死链（AGENTS.md 互链用全路径 wiki 链接）；
3. 无与 skill / 子页重复的「双份真相」；
4. 行数达标：根文件 100 行内，模块页只列关键项；
5. front-matter 的 `updated` 已更新。
